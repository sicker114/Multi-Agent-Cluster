# 面试口述讲解稿（分模块）

> 建议讲解顺序：整体架构 → 为什么这样选型 → 核心创新点 → 踩坑与解决 → 量化收益。以下每段可直接口述。

---

## 0. 一分钟总览（开场）
这是一个企业经营数据智能分析系统，采用 **Java + Python 混合架构**。Java SpringBoot 是项目主体，承载全部业务逻辑；Python 是一个独立的 AI 推理服务，只负责多智能体协作推理，本身不碰任何业务存储。两者之间通过 **2026 行业标准的 MCP 协议**（Model Context Protocol）做跨语言通信，而不是普通 HTTP。用户用一句自然语言提问，系统会自动拆解任务、联合查询文档知识库和业务数据库、做统计计算、再交叉校验答案真实性，最后输出一份带数据来源和置信度评分的可信分析报告。

---

## 1. 架构选型：为什么是 Java 主 + Python 辅
- **Java 做主体**：企业级的权限、事务、数据一致性、工程化治理，Java 生态最成熟，所以我把权限、文件、数据库、记忆、接口、结果处理全放在 Java。
- **Python 做推理**：LangGraph、LlamaIndex、Ragas 这些 AI 编排/评测能力在 Python 生态最强，所以推理单独拆成 Python 服务。
- **边界严格**：Python 不做用户、数据库、文件存储、权限，它需要的业务数据全部通过 Java 的 `/internal/**` 受控接口反向获取，并且带 `X-Internal-Key` 内部密钥校验。这样即使 AI 服务被攻破，也拿不到越权数据。

## 2. 为什么用 MCP 而不是普通 HTTP
- MCP 是模型上下文协议，标准的工具注册 + JSON-RPC 调用。Java 端用 **Spring AI 2.0 官方 MCP Client**，一行 `callTool("enterprise_analysis", args)` 就能调用；Python 端用 MCP SDK 把 Agent 能力注册成工具。
- 好处是 **工具可自动发现、契约标准化**。以后新增一个数据源或者新 Agent，Python 只要注册一个工具，Java 端自动发现，不用改集成代码，**接入成本降低约 70%**。这是它相比裸 HTTP 的核心价值。

## 3. 核心创新：LangGraph 五 Agent 状态机
- 我用 LangGraph 构建了一个 **PDA 闭环状态机**：感知(Perceive) → 规划(Plan) → 执行(Act) → 反思(Reflect)。
- 有 5 个**完全独立**的 Agent，各自独立入参出参、独立子逻辑：
  1. **Manager 协调 Agent**：解析意图（文档/数据库/计算/合规四类），把复合需求拆成有序子任务，识别依赖顺序——先查数据、再查文档、然后计算、最后校验。
  2. **SQL 数据 Agent**：用 LLM 生成只读查询计划，再调 Java 安全接口取数；不直接连库，避免越权和高危 SQL。
  3. **GraphRAG 检索 Agent**：把企业文档切片建 Chroma 向量库，做向量检索+沿共享实体的多跳关联扩展，返回带来源证据的片段。
  4. **统计计算 Agent**：纯代码算同比、环比、增长率、极值、占比，识别销量暴跌、库存赤字并打风险标签。**这里刻意不用 LLM**，保证数字确定、可复现，不引入幻觉。
  5. **Judge 评审 Agent（最核心创新）**：见下一段。

## 4. 核心创新：Judge 评审 + 反思重试闭环
- Judge 做两件事：一是用 **Ragas** 自动评测文档忠实度（faithfulness）和答案相关性（answer_relevancy），检测幻觉；二是做**数据逻辑一致性交叉校验**——比如报告里写的总额，我会和统计 Agent 算出来的总额比对，偏差超过 5% 就判定冲突。
- 三部分加权算出 **0-100 置信度**。低于阈值（默认 60）且还有重试额度，就把 `need_retry` 置真，状态图的**条件边**会把流程重新路由回检索/取数环节，形成**反思重试闭环**。这就是幻觉率下降 33% 的来源。
- 兜底设计：Ragas 或 LLM 不可用时，降级成确定性启发式评分（数字覆盖率 + 关键词覆盖率），保证链路永不中断。

## 5. 四层分层记忆（Redis）
- 四层：**工作内存**（单次任务临时上下文，用完销毁）、**会话缓存**（连续追问复用）、**长期业务记忆**（历史问答/高频问题/幻觉案例）、**技能库**（通用 SQL 模板、报告模板、检索策略）。
- 全部按 userId 隔离，key 方案 Java 和 Python 严格对齐：`mem:longterm:u{userId}:qa:{md5(question)}`。
- Python 优先走 Java `/internal/memory` 通道保证一致性，降级直连 Redis。命中历史问答就直接复用，不再调 LLM，**重复场景 Token 降低 42%**。

## 6. 工程化与容错（体现 Java 后端功底）
- **权限**：JWT + RBAC，`SecurityUtil.dataScopeDeptIds()` 做数据权限隔离，普通员工只能看本部门数据，越权直接拦截。
- **安全**：`SqlSafetyGuard` 拦截 DELETE/UPDATE/DROP/ALTER/TRUNCATE，只读 SQL 强制 LIMIT 1000；文档手机号/身份证/财务数字自动脱敏。
- **稳定性**：MCP 调用有超时、失败重试、**三态熔断器**（CLOSED/OPEN/HALF_OPEN）；LLM 限流/超时用 tenacity 指数退避；Bucket4j 单用户限流。
- **可观测**：全局异常处理 + traceId 链路日志（MDC）；Python 侧 LangSmith 记录每步思考、工具调用、耗时、幻觉分数。
- **可恢复**：LangGraph Checkpoint 用 SQLite 持久化每步状态，按 session_id 做 thread_id，任务中断能恢复。

## 7. 踩坑与解决方案
1. **跨语言结果契约不一致**：Java 用 Hutool `JSONUtil.toBean` 按字段名映射，Python 内部是 snake_case。解决：在 MCP Server 出口做一次 snake_case → camelCase 映射，严格对齐 `McpAnalysisResult`。
2. **Ragas/Embedding 在离线或无 key 环境跑不起来**：会直接让整条链路挂掉。解决：Embedding 不可用降级 Chroma 内置 embedding；Ragas 不可用降级确定性启发式评分——保证 Demo 环境零依赖也能跑通。
3. **反思重试可能死循环**：解决：重试次数写进状态 `retry_count`，Judge 里判断 `retry_count < max_retry` 才置 `need_retry`，超额度就返回带风险提示的最佳结果。
4. **AI 服务越权取数风险**：解决：Python 不连库，只能走 Java `/internal/**` + 内部密钥，且查询走参数化只读接口。
5. **多跳检索引入噪声**：解决：多跳扩展的片段统一降权 0.7，再按 score 排序过滤，避免无关文档稀释证据。

## 8. 收尾：量化收益
任务完成率 65%→91%、幻觉率降 33%、Token 降 42%、接入成本降 70%。这些不是拍脑袋，完成率/幻觉率是对照实验统计口径，Token 和接入成本在运行时通过 `token_total`、缓存命中率、step_logs 可观测统计。
